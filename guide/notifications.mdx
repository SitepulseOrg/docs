SitePulse notifies your team when automatic monitoring opens or resolves issues, and when manual checks complete or fail in the background.

## Notification configurations

Admins and owners configure notification destinations under **Notifications** in the sidebar.

You can add multiple destinations across these channels:

| Channel | Description |
|---------|-------------|
| **Email** | Send alerts to one or more email addresses |
| **Slack** | Connect the SitePulse Slack app and choose a channel |
| **Slack webhook** | Send to a Slack incoming webhook URL |
| **Microsoft Teams** | Send to a Microsoft Teams incoming webhook URL |
| **Webhook** | Generic HTTP endpoint (GET or POST) |

Each configuration can:

- Subscribe to **Issue detected** and/or **Issue resolved** events
- Apply to all check tools or only specific tools (Status, SSL, DNS, Broken Links, Performance)
- Be enabled or disabled independently
- Be tested directly from the settings screen

Notification configurations determine **where** alerts go. The conditions for opening issues (thresholds, confirmation retries, follow-up timing) are controlled in **[Monitoring](/guide/monitoring)**.

## When notifications are sent

### Issue lifecycle notifications

When automatic monitoring opens an issue or marks one resolved, SitePulse sends notifications to all enabled destinations that subscribe to the matching event and tool scope.

| Event | When it fires |
|-------|---------------|
| **Issue detected** | A new issue opens, or a previously resolved issue reopens |
| **Issue resolved** | Automatic checks confirm the underlying problem has cleared |
| **Issue escalation** | A follow-up reminder while an open or acknowledged issue has not recovered (see below) |

<Note>
  Exact trigger rules are defined in your team's monitoring settings (thresholds, confirmation retries, follow-up timing). See [Managing issues](/guide/issues) for how issues relate to notifications.
</Note>

### Issue escalation

When [escalation](/guide/monitoring#escalation) is enabled on the Monitoring page, SitePulse schedules follow-up reminders at the intervals you select (15 minutes through daily).

Escalation reminders are delivered to notification configurations subscribed to **Issue detected**. No separate channel setup is required.

Reminders stop when the issue is resolved or is no longer in an active state (`open` or `acknowledged`). Quiet time suppresses escalation the same way it suppresses initial issue alerts.

### Manual check notifications

When you run a manual check, SitePulse can notify the team on completion or failure (for longer-running checks like SSL, broken links, or performance that finish in the background).

These notifications do not depend on automatic monitoring thresholds and do not open issues.

## Notification channels

### Email

Add email addresses that receive issue alerts.

Each email notification typically includes:

- Summary of what was detected
- Severity (critical / warning / info)
- The affected site
- Key details from the check result

### Slack

**Slack app** — Click **Connect Slack** when creating a configuration, authorize the SitePulse app, and pick a channel. No webhook URL is required.

**Slack webhook** — Paste a Slack incoming webhook URL if you prefer webhook-based delivery.

### Microsoft Teams

Add a Microsoft Teams incoming webhook URL. SitePulse formats messages for Teams workflow webhooks.

### Generic webhook

Add webhook endpoints to receive HTTP notifications (GET or POST) for issue lifecycle events.

Use webhooks to integrate with PagerDuty, custom automation, or other systems.

See [Webhook notifications](/guide/webhooks) for configuration fields, payload schemas, headers, delivery behavior, test vs production payloads, and URL requirements.

### In-app notifications

While using the SitePulse dashboard, issue lifecycle notifications appear in real time and update counts on the dashboard (subject to quiet time and your permissions).

## Quiet time

**Quiet time** (configured in **Monitoring**) suppresses outbound notifications during defined windows.

Use it for:

- Overnight or weekend periods when the team is unavailable
- Planned maintenance windows

Checks continue to run during quiet time — only outbound notifications are suppressed. Issues can still open, acknowledge, and resolve.

## Managing notification configurations

From the Notifications page, admins and owners can:

- Add new destinations for any supported channel
- Edit existing configurations (channel, events, tools, enabled state)
- Test a configuration (webhook, Slack webhook, Slack app, and Microsoft Teams channels)
- Remove configurations that are no longer needed

Each configuration is independent, so you can route different tools or environments to different destinations.
