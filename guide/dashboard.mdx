The SitePulse dashboard is your at-a-glance workspace for site health. It surfaces problems, highlights team-wide metrics, shows your pinned priority sites, and provides quick actions.

## What you see on the dashboard

After logging in with a current team and active subscription, the dashboard shows:

<AccordionGroup>
  <Accordion title="Health overview">
    Summary metrics for the current team:
    - **Total sites monitored** — links to the full sites list
    - **Uptime this month** — aggregate uptime percentage from automatic status checks
    - **Checks run today** — total automatic and manual checks completed today
    - **Open issues** — active incidents (open + acknowledged); links to the Issues page
  </Accordion>

  <Accordion title="Problem summaries">
    Deferred cards that highlight sites needing attention:
    - Sites that are currently down (status failures)
    - Sites with invalid or expiring SSL certificates
    - Sites with DNS issues (failed lookups or expected-record mismatches)
    - Sites with broken links (total count across affected sites)
    - Sites with low performance scores or slow response times

    Each problem card includes shortcuts to run a manual check for that tool.
  </Accordion>
  
  <Accordion title="Pinned sites">
    Your most important sites stay visible here:
    - Shows latest status and uptime percentage over recent periods
    - Links into detailed site information
    - Uptime stats are calculated from recent status checks
  </Accordion>
  
  <Accordion title="Quick actions">
    Management shortcuts:
    - **Add site** — start the site creation flow
    - **Configure monitoring** — open team monitoring settings
    - **Notifications** — configure alert destinations
    - **View issues** — open the incident list
  </Accordion>
</AccordionGroup>

<Info>
  If there are no active problems and you have pinned sites, the dashboard stays clean and focused on your priorities.
</Info>

## Notifications setup reminder

When your team has no notification destinations configured, the dashboard may show a reminder banner prompting you to set up alerts. Admins and owners can dismiss the banner per team; the dismissal lasts for one year.

Configure destinations under **Notifications** in the sidebar. See [Notifications](/guide/notifications).

## Pinning sites

Pinning controls what appears in the dashboard's pinned section and pushes important sites to the top of the sites list.

**How to pin sites:**

- From the sites list (or table row actions), use the row menu to **Pin** or **Unpin** a site
- You can also toggle pin state while editing a site
- Pinned sites sort first (by pin time, newest pins first), then newest unpinned sites

<Tip>
  Use pinning for production sites, key clients, or anything you want visible without filtering.
</Tip>

The dashboard shows a "Pin the sites you want on the dashboard" callout until you have at least one pinned site.

The sidebar also provides direct access to:

- Sites list and creation
- **Monitoring** — automatic check cadence, thresholds, and quiet time
- **Notifications** — alert destinations
- **Issues** — active incidents with acknowledge and resolve actions
- Individual manual diagnostic tools (Status, SSL, DNS, Broken Links, Performance)

## Real-time updates

The dashboard polls for updates every **30 seconds** while you keep the page open. Problem summaries, health overview metrics, and pinned site status refresh automatically.

## Tips

<Steps>
  <Step title="Start with critical sites">
    Add your critical sites and pin the top 3–5 for immediate visibility.
  </Step>
  <Step title="Use manual tools when needed">
    Use the manual tools area (or the **Run Check** dropdown on any site detail) when you need an on-demand result instead of waiting for the next automatic check.
  </Step>
  <Step title="Use Issues for incident triage">
    When problem summaries need follow-up, open **Issues** for filtering, acknowledgement, and bulk resolve actions.
  </Step>
  <Step title="Remember the dashboard is a summary">
    The dashboard does not replace the full sites list, the Issues page, or individual check histories — it is a curated summary for fast situational awareness.
  </Step>
</Steps>
