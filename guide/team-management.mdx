Teams allow you to collaborate with others and share monitoring responsibilities. Each team has its own sites, monitoring settings, billing, and member access controls.

<Info>
  See also [Account and Preferences](/guide/account-settings) for per-user profile, password, and appearance settings.
</Info>

## Creating or joining a team

New users verify their email before creating or joining a team. After verification, SitePulse sends users without a team to team creation unless they have a pending invitation.

Invited users can join from:
- The invitation email
- The invitations page in SitePulse

<Warning>
  An invitation can only be accepted by the email address it was sent to.
</Warning>

## Roles

SitePulse uses three practical access levels:

<CardGroup cols={3}>
  <Card title="Owner" icon="crown">
    Manage the team, billing, members, security, monitoring, notifications, sites, and checks.
  </Card>
  <Card title="Admin" icon="user-shield">
    Manage team settings, members, monitoring, notifications, sites, and checks.
  </Card>
  <Card title="Member" icon="user">
    Work with sites, checks, and notifications without managing team administration or billing.
  </Card>
</CardGroup>

<Note>
  **Owners** are the only users who can manage billing. Team deletion is owner-only.
</Note>

## Members and invitations

Admins and owners can invite members by email and choose a role. 

**Managing invitations:**

- Pending invitations can be revoked by users with member-management permission
- Invitees can decline their own invitations
- When a member's role changes, SitePulse emails that member so they know their access changed

## Monitoring

Team monitoring settings define the default automatic-check behavior for the team. Admins and owners can update:

| Setting | Description |
|---------|-------------|
| **Cadence** | How often each check tool runs |
| **Enabled tools** | Which tools are monitored automatically |
| **Status headers** | Default headers for status checks |
| **Problem thresholds** | When to trigger notifications for failures |
| **Quiet time** | When to suppress notifications |
| **Confirmation retry** | How soon to recheck a failed uptime result before opening an issue |
| **Follow-up timing** | How often to check during incidents |

<Tip>
  Individual [sites](/guide/sites) can override some monitoring settings when a site needs different behavior from the team default. See [Problem thresholds](/guide/checks#problem-thresholds) for the full threshold reference.
</Tip>

## Notifications

Admins and owners set up notification configurations under **Team Settings → Notifications**. These control where alerts are sent when automatic monitoring detects problems (or when problems recover) and for manual check results.

<Tabs>
  <Tab title="Email notifications">
    Add email addresses that receive problem alerts.
    
    **Email notifications typically include:**
    - Problem summary and severity
    - Affected site
    - Key details from the triggering check
  </Tab>
  <Tab title="Webhook notifications">
    Add webhook URLs to receive HTTP alerts for integrations (Slack, PagerDuty, custom automation, etc.).
    
    **Webhook options:**
    - Method: `GET` or `POST`
    - Filter to specific tools or all tools
    - Events for problem detection and recovery
  </Tab>
</Tabs>

Each notification configuration can target all tools or selected tools only. Admins and owners can enable, disable, test, edit, or remove configurations at any time.

See the [Notifications](/guide/notifications) guide for full details on channels, quiet time, and when alerts fire.

## Billing

Billing is managed by the team owner. The billing page shows:

- Current plan and available plans
- Plan limits (sites, members, cadence)
- Payment method details
- Invoice history
- Checkout and Stripe billing portal (when available)

### Plans and cadences

SitePulse offers three pricing tiers with different minimum automatic monitoring cadences. All check tools are enabled across all plans.

| Plan | Minimum cadence |
| :--- | :-------------- |
| **Starter** | 30 minutes |
| **Growth** | 5 minutes |
| **Agency** | 1 minute |

<AccordionGroup>
  <Accordion title="Plan limits">
    Plan limits affect:
    - Number of sites you can monitor
    - Number of team members
    - Automatic monitoring cadence (how often checks run)
    - Check history retention
    - Priority queue access
  </Accordion>
</AccordionGroup>

## Security

Teams can require two-factor authentication (2FA) for all members. When this setting is enabled, users must enable 2FA before continuing to team-scoped dashboard areas.

<Steps>
  <Step title="Navigate to security settings">
    Owners and admins can find security settings under **Team Settings → Security**.
  </Step>
  <Step title="Enable 2FA requirement">
    Toggle the "Require two-factor authentication" setting.
  </Step>
  <Step title="Team members enable 2FA">
    Once enabled, all team members will be prompted to set up 2FA on their next login.
  </Step>
</Steps>

<Warning>
  Users who haven't enabled 2FA will not be able to access team areas until they complete setup.
</Warning>

## Switching teams

If you belong to multiple teams:

1. Use the **team switcher** in the sidebar header (visible when you have more than one team)
2. Select a different team to change your "current team" context
3. Sites, monitoring settings, and billing are always scoped to the current team

<Tip>
  You can leave a team from the switcher menu (owner removal or self-removal rules apply per policy).
</Tip>
